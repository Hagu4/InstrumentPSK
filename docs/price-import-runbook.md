# Обновление цен: инструкция администратора

Раздел находится в закрытой админке: **App → Обновление цен**. Он меняет только `price`, `old_price`, постоянную скидку и дату обновления цены. Товары, остатки, названия, фотографии, категории и характеристики не создаются и не удаляются.

## Загрузка Excel поставщика

1. Откройте «Обновление цен» и нажмите «Загрузить прайс поставщика».
2. Выберите исходный `.xlsx`. Цена берётся только из `REKOMEND_CENA`.
3. Просмотрите сводку. До нажатия «Применить цены» каталог не изменяется.
4. Для строк «Требует проверки» выберите предложенного кандидата и нажмите «Сопоставить». Если кандидата нет, откройте «Найти товар», найдите его в новой вкладке и укажите ID. Ненужную строку можно явно пропустить.
5. Отдельно подтвердите изменения более чем на 50%.
6. Сверьте несколько товаров, старые и новые цены, после чего нажмите «Применить цены».

Повторная загрузка того же файла открывает уже существующую операцию. Система не создаёт дубль.

## Ручное пакетное изменение

1. Нажмите «Изменить цены вручную».
2. Найдите товар по названию, артикулу или бренду.
3. Выберите от 1 до 100 товаров и укажите новую основную цену для каждого.
4. Проверьте предпросмотр и примените пакет.

Процент скидки выбирается один раз в диапазоне 10–30% и сохраняется. Зачёркнутая цена пересчитывается автоматически с округлением вверх до 10 рублей.

## Откат

Откатить можно только последнюю применённую операцию. Откат восстанавливает основную цену, зачёркнутую цену, скидку и прежнюю дату обновления. Если хотя бы одна затронутая цена после импорта менялась отдельно, откат остановится без частичного изменения каталога.

После отката более старые операции намеренно не разблокируются: это защищает каталог от каскадного возврата к устаревшим ценам.

## Права

Сотруднику выдаются только необходимые разрешения:

- просмотр обновлений цен;
- создание предпросмотра Excel;
- создание ручного пакета;
- разрешение спорных строк;
- применение;
- откат.

Все изменяющие действия выполняются POST-запросами с CSRF-защитой. Применённая и отменённая история редактированию не подлежит.

## Локальная проверка перед production

```powershell
python DjangoWebProject1/manage.py migrate
python DjangoWebProject1/manage.py check
python DjangoWebProject1/manage.py test app.test_price_sync_models app.test_price_sync_rules app.test_price_sync_parsing app.test_price_sync_matching app.test_price_sync_preview app.test_price_sync_manual app.test_price_sync_admin app.test_price_sync_apply app.test_price_sync_rollback app.test_price_sync_retention app.test_price_sync_integration --noinput
python DjangoWebProject1/manage.py runserver 127.0.0.1:8000
```

Откройте `http://127.0.0.1:8000/management-psk-zone/app/priceimport/`. Для первой проверки используйте копию файла с несколькими строками и не нажимайте «Применить», пока предпросмотр не сверён.

## Развёртывание

Перед production-развёртыванием:

1. Сделайте резервную копию PostgreSQL и запишите текущий commit приложения.
2. Разверните чистый проверенный commit.
3. Выполните `python manage.py migrate` и `python manage.py collectstatic --noinput` внутри контейнера приложения.
4. Проверьте `python manage.py check --deploy` с production-переменными.
5. Откройте раздел истории и создайте предпросмотр небольшого файла без применения.
6. Только после проверки выполните полный импорт.

Исходные Excel хранятся вне публичной media-директории. Подробные строки и файлы остаются у 12 последних успешных Excel-операций; сводки остаются навсегда. Ручная история сохраняется полностью. Ручная очистка:

```powershell
python DjangoWebProject1/manage.py cleanup_price_imports --keep 12
```

Команда идемпотентна и не удаляет товары или связи с поставщиком.

## Аварийная остановка

Если предпросмотр выглядит неверно, ничего не применяйте: черновик не меняет каталог. Если ошибка замечена сразу после применения и цены больше никто не редактировал, используйте кнопку отката. При конфликте остановитесь, сохраните журнал операции и восстановите нужные значения из резервной копии либо новым проверенным ручным пакетом.
