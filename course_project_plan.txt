#### **1.2.2. Информационные требования**

**Что делать:** Скопируйте готовый текст ниже. Он подробно описывает каждую информационную сущность вашего проекта.

**Готовый текст:**

> Информационная структура сайта спроектирована для хранения всех необходимых данных для работы интернет-магазина. Она включает в себя следующие ключевые сущности:
> 
> *   **Пользователь (User) и Профиль (Profile):** Основой является стандартная модель `User` из Django, хранящая данные для аутентификации (логин, пароль, email). Она расширена моделью `Profile` через связь "один-к-одному" для добавления специфичных для проекта полей, таких как `Номер телефона`.
> 
> *   **Категория (Category):** Данная сущность организует товары в иерархический каталог. Ключевые атрибуты включают `Название`, `Описание` и `URL-псевдоним` (slug). Наличие поля `parent_id` (внешний ключ на саму себя) позволяет создавать вложенные подкатегории, обеспечивая гибкую структуру каталога (например, "Электроинструменты" -> "Дрели").
> 
> *   **Товар (Product):** Центральная сущность, представляющая товарную позицию. Она содержит все коммерчески важные данные: `Название товара`, `Описание`, `Цена`, `Количество на складе` и `Изображение`. Каждый товар обязательно связан с одной `Категорией` (связь "многие-к-одному") и может иметь множество `Характеристик` и `Отзывов`.
> 
> *   **Характеристика (Characteristic) и Характеристика Товара (ProductCharacteristic):** Эта пара сущностей реализует механизм "ключ-значение" для технических параметров товаров. `Characteristic` — это справочник названий характеристик (например, "Мощность", "Вес"), а `ProductCharacteristic` — это конкретное значение данной характеристики для конкретного товара (например, "2000 Вт"). Это позволяет добавлять товарам произвольное количество параметров.
> 
> *   **Заказ (Order) и Элемент Заказа (OrderItem):** Сущность `Order` агрегирует информацию о покупке: кто (`Пользователь`), когда, на какую сумму, статус (`Оплачен`, `Отменен` и т.д.), а также детали доставки и оплаты. Сущность `OrderItem` детализирует состав заказа через связь "многие-ко-многим" с `Товаром`, указывая, какой именно товар и в каком `Количестве` был заказан.
> 
> *   **Отзыв (Review):** Сущность для сбора обратной связи от пользователей по конкретным товарам. Включает `Текст отзыва`, `Рейтинг` (от 1 до 5), `Автора` и `Дату`. Каждый отзыв жестко привязан к одному товару и одному пользователю.
> 
> *   **Обратная связь (Feedback):** Обобщенная сущность для сбора мнений о работе сайта в целом. Содержит поля для имени, email, общей оценки и комментариев.

**Алгоритм для блок-схемы (вид `catalog`):**
1.  Начало.
2.  Проверка, является ли метод запроса `POST` (добавление в корзину).
    *   **Да:** Выполняется логика добавления товара в корзину и происходит перенаправление на страницу корзины.
    *   **Нет (GET):** Выполняется основная логика отображения каталога.
3.  Из базы данных извлекается полный список товаров.
4.  Проверяется наличие в URL-адресе фильтра по категории.
    *   **Да:** Список товаров фильтруется для отображения только продуктов из выбранной категории.
5.  Проверяется наличие поискового запроса.
    *   **Да:** Список товаров дополнительно фильтруется по совпадению в названии, описании и т.д.

**Алгоритм для блок-схемы (вид `product_detail`):**

        3.  Если форма отзыва валидна, он сохраняется в БД, и происходит перенаправление на эту же страницу.
        4.  Если форма невалидна, страница отображается повторно с ошибками.
    *   **Нет (GET):**
        1.  Отрисовывается HTML-шаблон `product_detail.html` с информацией о товаре.

**Алгоритм для блок-схемы (вид `cart`):**
