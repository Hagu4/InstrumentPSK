# Работа с изменениями

1. Создайте ветку `feature/<описание>` от `develop`.
2. Делайте небольшие коммиты с одной задачей.
3. Не добавляйте `.env`, базы, media, ключи, сертификаты и ZIP-архивы.
4. Запустите тесты и проверку Django перед merge.
5. Изменения попадают в `release/production` только после проверки staging.

## Защищённые ветки и обновления

`main` и `release/production` принимают изменения через Pull Request с успешной
проверкой `test` из workflow `quality`. Ветка PR должна быть актуальна относительно
целевой ветки, а обсуждения — разрешены. Правила действуют и для администратора;
принудительная перезапись и удаление этих веток запрещены.

Обязательное одобрение второго участника не требуется: проект можно сопровождать
одному. Это не отменяет PR, проверки CI и ручного просмотра изменений.

Dependabot предлагает обновления Python-зависимостей, GitHub Actions и Docker-образа
в PR к `main`, проверяя версии по понедельникам в 09:00 по Москве. Обновления
безопасности могут появляться вне этого расписания. Автослияние и автоматическая
выкладка не настроены; особенно внимательно проверяйте новые основные версии.
После слияния таких PR переносите изменения из `main` в `develop` через PR,
а в `release/production` — после проверки staging.

Никогда не публикуйте секреты в issue, commit, логе CI или чате. Если секрет попал
в историю, его нужно сначала отозвать, затем очистить историю.
